# 06_PublishingSupport

Publishing tooling and per-site data, grouped by destination site.

Pattern for each site:
- **Site root** = what you use day to day (status, launchers, PublishHelp, secrets/reference)
- **`Workflow/`** = behind-the-scenes scripts, config, templates, plans

```text
06_PublishingSupport/
|-- NexusMods/
|   |-- README.md                    what to open / run for Nexus
|   |-- Nexus-Status.md              live ReleaseSource vs Nexus picture
|   |-- RUN-Nexus-Status/Update*.bat day-to-day launchers
|   |-- PublishHelp/                 one generated .md packet per mod
|   |-- nexusAPI.txt / api key       reference + secret
|   `-- Workflow/                    scripts, config, status JSON, templates, plans
|-- ModNetwork/
|   |-- Api Informaiton.txt
|   `-- Workflow/
|-- 7DaysToDieMods/
|   |-- README.md                    what to open / run for 7DaysToDieMods
|   |-- RUN-7DaysToDieMods-Update.bat satellite repos + GitHub Releases
|   |-- PublishHelp/                 one generated .md packet per mod
|   `-- Workflow/                    generator, update script, config
`-- Site-Automation-Capabilities.md
```

## NexusMods

Open [`NexusMods/README.md`](NexusMods/README.md). Start with `Nexus-Status.md` and `RUN-Nexus-Status.bat`.

## ModNetwork

Root (`06_PublishingSupport/ModNetwork/`): `Api Informaiton.txt`.

`Workflow/`:
- `SCRIPT-ModNetwork.py` - init-config / build-plan / check-live / prepare-upload / update-page modes (see its `--help`).
- `FieldMapping.txt` documents where each published field is sourced from.
- `modnetwork-config.json`, `modnetwork-plan.json`, `TEMPLATE-ModNetworkConfig.json`, `ModNetwork-Automation-Capabilities.md`.

## 7DaysToDieMods

Open [`7DaysToDieMods/README.md`](7DaysToDieMods/README.md). Publish regenerates `PublishHelp/*.md` and creates missing empty satellite repos. `RUN-7DaysToDieMods-Update.bat` creates missing GitHub Releases from `04_DownloadZips`.

## `__pycache__`

Python's auto-generated bytecode cache. Harmless, already covered by the repo-wide `__pycache__/` gitignore rule, but every script under this folder now sets `sys.dont_write_bytecode = True` and the launchers set `PYTHONDONTWRITEBYTECODE=1`, so it shouldn't reappear during normal use.
