# 7D2D v3.1 — Screamer / Heatmap System (Researched)

**Game version:** 7 Days to Die v3.1  
**Sources:** `Decompiled_AssemblyCSharp_7d2d.v3.1` + vanilla XML (`blocks.xml`, `spawning.xml`, `entitygroups.xml`, `gamestages.xml`, `sounds.xml`)  
**Researched:** 2026-08-04

## Official description (screamer spawning)

Assuming default sandbox Heatmap Sensitivity, within an 80×80 block area (5×5 chunks), 5 lit campfires can trigger a screamer check almost immediately, with a 20% chance of spawning. On a fail, the next check takes about 4–7 minutes; on a success, about 22–25 minutes. Higher game stage changes which screamers can appear (normal → more screamers → feral → radiated). Each screamer can summon up to 25 zombies total, at 5 per scream. A scream has a 12% chance of spawning another screamer. (63 torches have similar results.) Additional heat sources in the same area do not increase the spawn chance. However, more screamer checks can run if heat is built about 100+ blocks away, since that uses a separate heat area.

Heatmap Sensitivity changes how many sources are needed for that same near-immediate check (one heat wave to 25); it does not change the 20% chance or cooldowns:

- Very High (2×): 3 campfires (32 torches)
- High (1.5×): 4 campfires (42 torches)
- Default (1×): 5 campfires (63 torches)
- Low (0.5×): 10 campfires (125 torches)
- Disabled (0×): no heatmap / no heat-based screamers


---

## Core pipeline

1. Heat sources call `AIDirector.NotifyActivity(...)`.
2. Activity accumulates per heat **area** on `AIDirectorChunkData`.
3. Every ~5s, if activity ≥ **25**, director rolls **20%** to spawn scouts (`AIDirectorChunkEventComponent.CheckToSpawn`).
4. On any check (pass or fail), heat for that area is **wiped to 0** and a cooldown starts. During cooldown, new heat is **ignored** (`IsReady == false`).
5. Spawned scouts are `IsScoutZombie`; they investigate the heat point, then scream-summon via `AIScoutHordeSpawner`.

Blocked during blood moon / Twitch boss horde; requires enemies + horde meter enabled; scaled by sandbox **Heatmap Sensitivity**.

## Area size

- `cChunksPerArea = 5` → **5×5 chunks**
- Chunk = 16 blocks → **80×80 blocks**
- No LOS / walls / windows — heat ignores blocks

## Heat sources (defaults, Sensitivity 1×)

| Source | Heat per pulse | Pulse timing |
|---|---|---|
| Campfire | +5 | First burn tick can be immediate; then ~2.8 min (`GetActivityWorldTimeDelay`) |
| Forge | +6 | Same as campfire |
| Chem / workbench / mixer | +5 | Same |
| Dew collector / apiary | +0.8 | When producing |
| Player torch / burning barrel (`TorchHeatMap`) | +0.4 (`Strength × 0.4`) | ~1 min realtime |
| Player candle | +0.2 | ~1 min |
| Explosion sounds | +5 | Immediate per explosion |
| Gunfire / other noisy sounds | varies (`heat_map_strength`) | Immediate per play |

**XML note:** Block `HeatMapTime` / `HeatMapFrequency` are largely legacy in v3.1. `Block` only parses `HeatMapStrength`. Workstation emit rate uses `AIDirector.GetActivityWorldTimeDelay()` (scales with day length; ~1000 world-time ≈ **~2.8 real min** on default 60-min day).

Heat **decays** over event duration (workstations default **720s**; sound heat **240s**). That decay caps a lone campfire around **~24** (under the 25 threshold).

## Hitting 25 fast

- **5 campfires** or **5 forges** in one area ≈ one pulse wave to 25
- **63 player torches** ≈ one torch-pulse wave to 25 (slower/worse than campfires)
- **5 explosions** ≈ near-instant 25
- 1 campfire alone usually never triggers (steady ~24)

## Check / cooldown timings (5 campfires, defaults)

| Scenario | Time to next check |
|---|---|
| Initial light of 5 campfires | Almost immediate (seconds; director checks ~every 5s) |
| After **failed** check | ~**4–7 min** (240s lockout + ~0–2.8 min rebuild) |
| After **successful** check | ~**22–25 min** (1320s lockout + rebuild) |

Exact constants (`AIDirectorChunkData`):

- Fail this area: **240s**; neighbors **180s**
- Success this area: **1320s**; neighbors **720s**

Spawn also wants a living player within **~120m** of the heat point.

## Scout / screamer spawn tables

From `SpawnScouts` by local gamestage:

| Gamestage | Spawner | Typical result |
|---|---|---|
| &lt; 45 | `Scouts1` | 1× normal screamer |
| 45–84 | `Scouts2` | up to 2 screamers |
| 85–124 | `ScoutsFeral` | feral |
| ≥ 125 | `ScoutsRadiated` | radiated |

XML: `spawning.xml` → `entitygroups.xml` (`ZombieScouts*`).  
Summoned horde composition: `gamestages.xml` → `ScoutGSList`.

## After screamer is alive

Constants (`AIDirectorConstants` / `AIScoutHordeSpawner`):

- Grace before first scream: **2s**
- Scream interval: **18s**
- Per scream: **5** zombies (`ScoutGSList`)
- **12%** chance: one slot becomes **another scout** (4 horde + 1 scout)
- Cap: **25 total summoned per scout** (lifetime counter; killing does **not** refresh)
- Two screamers from one check = separate 25 caps each

## Heatmap Sensitivity (sandbox)

`DisabledLowDefaultHigh`: **0 / 0.25 / 0.5 / 1 / 1.5 / 2**  
Multiplies all heat via `AIDirector.HeatMapSensitivityModifier`. Default **1**. Disabled (0) stops heat scout system.
